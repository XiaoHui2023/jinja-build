# jinja-build Doc

## 设计特性

### 仓库发现

文档生成器面向一个模板根目录工作。它会向下寻找带数据结构文件的目录，并把每个目录当成一个独立仓库。

发现仓库后，不再继续深入寻找新的仓库。这样一个仓库里面可以放自己的子目录，不会被拆成多份文档。

### 独立渲染

每个仓库单独判断变化、单独生成文档。一个仓库出错时，只跳过这一份文档，不影响其他仓库继续更新。

失败会被记住。只要这个仓库内容没有变化，就不会反复重试和刷日志；等它更新后再重新生成。

### 稳定检查

一次文档生成结束后，会再看一眼仓库内容有没有变化。渲染期间如果有人改了文件，会立刻补一次生成。

这个规则让输出更接近最后一次保存后的状态。快速连续保存时，不需要手动触发第二次。

### 结构说明

文档会读取仓库里的数据结构文件，把可识别的数据模型整理成 Markdown。输出文件名来自仓库路径，目录层级会保留下来。

每个数据结构会列出类型说明和字段表。字段表会展示名称、类型、是否必填、默认值和说明，方便先扫一眼再看源码。

### 建模支持

当前支持 Pydantic 模型和 dataclass。两种来源会先转成统一结构，再交给 Markdown 生成器输出。

后续要支持新的建模方式时，可以单独新增转换器，不需要改动监听和输出逻辑。

## 配置

### `template`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-t`, `--template` | 要监听的模板根目录。 | 无 |

### `output`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-o`, `--output` | 文档输出根目录，会按仓库相对层级写出。 | 无 |

### `log`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-l`, `--log` | 日志输出目录，文件会按年月日和时分秒分层写入。 | 无 |

### `models_filename`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-mf`, `--models-filename` | 用于识别仓库的数据结构文件名。 | `models.py` |

### `interval`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-i`, `--interval` | 检查目录变化的间隔秒数。 | `1.0` |
