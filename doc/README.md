# jinja-build Doc

jinja-build Doc 监听模板根目录里的数据结构文件，并为每个模板仓库生成可扫读的 Markdown 结构说明。

- 自动发现带数据结构文件的模板仓库。
- 每个仓库独立生成，单个失败不影响其他仓库。
- 渲染期间发生变化会补一次生成，贴近最后保存状态。
- 支持 Pydantic 模型和 dataclass。
- 输出保留仓库相对层级，方便和模板目录对照。

## 设计特性

### 仓库发现

模板根目录下面，带数据结构文件的目录会被当成一个独立仓库。

发现一个仓库后，就不再继续深入拆分。这样仓库内部可以有自己的子目录，不会被误拆成多份文档。

### 独立渲染

每个仓库都有自己的变化判断和生成结果。

| 情况 | 结果 |
| --- | --- |
| 仓库有变化 | 重新生成文档 |
| 仓库生成失败 | 跳过这一份，其他仓库继续 |
| 失败后内容没变 | 不反复重试 |

等失败仓库再次更新后，会重新尝试生成。

### 稳定检查

一次生成结束后，会再确认仓库内容有没有在渲染期间变化。

```text
开始生成 -> 文件又变化 -> 立刻补一次生成
```

快速连续保存时，不需要手动触发第二次，输出更接近最后一次保存后的状态。

### 结构说明

生成出来的文档重点说明数据结构，而不是复述模板代码。

每个可识别的数据结构会整理出类型说明和字段表。字段表展示名称、类型、是否必填、默认值和说明，方便先扫一眼再看源码。

### 建模支持

Pydantic 模型和 dataclass 会先转成统一结构，再生成 Markdown。

这个分层让监听、变化判断和文档输出保持稳定。后续要支持新的建模方式时，可以单独新增转换器。

## 配置

### `template`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-t`, `--template` | 要监听的模板根目录。 | 无 |

### `output`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-o`, `--output` | 文档输出根目录，会按仓库相对层级写出。 | 无 |

### `log`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-l`, `--log` | 日志输出目录，文件会按 `年-月-日/时-分-秒.log` 分层写入。 | 无 |

### `models_filename`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-mf`, `--models-filename` | 用于识别仓库的数据结构文件名。 | `models.py` |

### `interval`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-i`, `--interval` | 检查目录变化的间隔秒数。 | `1.0` |
