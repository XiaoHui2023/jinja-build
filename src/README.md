# jinja-build 主入口

主功能在 `src/`：用 Jinja 模板和输入配置生成文件，适合把一组模板稳定地变成代码、配置或文档产物。

- 一次生成单个模板，也可以生成整个模板目录。
- 输入配置会先整理成模板更好使用的数据。
- 空白结果会自然跳过，适合可选文件。
- 多份输入可以批量生成，并按输出目录隔开。
- 模板多、输入多时会自动拆成并行任务。

## 设计特性

### 模板目录

把一个模板目录当成一件产物来生成。

目录里可以放多份模板，输出时保留相对层级。代码骨架、配置包、文档片段这类“一次生成一组文件”的产物，就不用拆成多次命令。

只想验证其中一份模板时，也可以直接给单个模板文件。

### 数据建模

模板拿到的是整理后的数据，不是原始配置。

```text
输入配置 -> 数据对象 -> 模板
```

输入配置可以像原料一样先被整理，常用计算也可以收在数据附近。模板就更像排版层，少写字段处理和判断逻辑。

### 配置格式

配置格式由加载器接住，模板流程不用跟着变。

只要加载器认得，输入配置就不限于某一种文件格式。后续仍会进入同一条数据整理流程。

YAML 支持 `!include` 引用同目录或其它相对路径文件；同一 mapping 下多行 `!include` 会深合并。也可用单文件捆绑：首行起用 `#文件名` 分段（如 `#a.yaml`），每段当作独立虚拟文件，入口为第一段。见 `examples/07-multifile-config`。

刚开始搭模板时，也可以先按空配置跑起来，再逐步补数据。

### 空白输出

让模板自己表达“要不要生成”。

```text
渲染后有内容 -> 写出文件
渲染后是空白 -> 跳过文件
```

可选文件、可选声明、附加清单都可以靠这个规则自然消失。判断看最终结果，全是空格或换行也算空内容。

### 批量渲染

一套模板可以套到多份输入上，每份输入都有自己的成品目录。

| 输入 | 输出 |
| --- | --- |
| 输入 A | 独立输出目录 A |
| 输入 B | 独立输出目录 B |
| 输入 C | 独立输出目录 C |

目录名来自输入文件名，方便对照来源。输出名不能重复，发现重名会提前报错，避免互相覆盖。

### 并行任务

任务会按“输入 × 模板”展开，能并行的部分一起跑。

- 单次输入：多份模板可以并行渲染。
- 批量输入：输入和模板的组合会一起调度。
- 并行数量会按可用 CPU 和任务数量收敛，尽量用上本机资源。

### 导入隔离

每个模板目录可以带自己的数据结构和小工具，不互相串。

即使不同目录里有同名数据结构文件，也会在独立名字下加载。同目录辅助文件只在加载期间临时可见，结束后环境恢复。

### 过滤器与 property

- 模板可用管道语法调用常用处理函数，例如 `{{ name | replace('a', 'o') }}`、`{{ items | len }}`。
- `models.py` 里**主数据类**的公开实例方法也可作过滤器，例如 `{{ '' | title }}`；仍支持 `{{ title() }}` 函数写法。
- 类上的 **property** 会进入模板变量，与字段一样用 `{{ label }}` 读取。

## 配置

### `template`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-t`, `--template` | 模板目录或单个模板文件。目录模式会扫描其中的模板文件。 | 无 |

### `input`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-i`, `--input` | 单个输入配置文件。会输出到指定输出位置。 | 空配置 |

### `batch`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-b`, `--batch` | 多个输入配置文件。会共用同一套模板，每个输入生成一个独立目录。 | 无 |

### `output`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-o`, `--output` | 单次模式下是输出位置；批量模式下是输出根目录。 | 无 |

### `models_filename`

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-mf`, `--models-filename` | 模板目录中的数据结构文件名。 | `models.py` |

### 调试输出

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--debug-input` `PATH` | 将配置文件经 `load_config` 解析后的 dict 写出为 `PATH`（尚未进入 `models.py`）。`PATH` 为绝对路径时原样使用；为相对路径时相对**当前工作目录**（执行命令时的路径）。 | 无 |
| `--debug-models` `PATH` | 将 `models` 实例化后、渲染模板前经 `to_dict` 整理的数据写出为 `PATH`（含 `@property` 等模板可见字段）。路径规则同 `--debug-input`。 | 无 |
